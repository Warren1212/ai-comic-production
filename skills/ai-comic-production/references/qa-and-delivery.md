# 审校与交付

## 首帧

- 人物：年龄、脸型、发型、衣服和体型一致；无多余人物、重复肢体或手指错误。
- 动作：起始姿势能自然接续。驾驶员打火的手须从驾驶位自然伸向点火区域，不能像从副驾驶伸来。
- 车辆：车型、车头、车厢、轮轴、反光镜、驾驶位和透视正确；需要驾驶员时驾驶室不能空。
- 空间：墙面展板、道路、货物、建筑和人物站位符合透视与安全常识。
- 文本：字、标点、引号、换行正确，无乱码或额外字。
- 风格与画幅：二维扁平风格统一，比例和分辨率符合本轮要求。

## 视频画面

抽取开头、中段、转场前后、动作高潮和结尾等多个时间点，必要时制作联系图：

- 镜头顺序和时间线正确，参考图未被混用。
- 人物不变脸、换装、增殖或穿模，只在说话时有嘴部动作。
- 车辆速度、跟拍逻辑、车轮和背景位移一致。
- 道具数量、方向、交接和事故现场中段无异常。
- 运镜平稳，转场无闪烁、跳变或空白帧。
- 精确文字全程稳定，无错字、重影和变形。

核心叙事错误即判失败，“大体能看”不能交付。

## 审查方法与状态

- 每张生成图均实看后再标通过。联系表用于总览和连续性，领口、手指、车辆铰链等疑点放大查看；低分辨率预览的疑似饰物不能未经放大就认定错误。批量标记只包含本次实际看过的明确ID，不能把审查期间新返回的未看图一起放行。
- 检查左右站位、景别和叙事作用：指定手部近景却生成半身景，即使人物正确也需返修。核对配角前后服装、帽子、眼镜，不只检查两位主角。
- 侧翻车的驾驶室、货厢、尾门、灯组和轮轴必须沿同一轴旋转，不能出现车头倒下、车尾仍直立；交接物的手部与承重关系、纸箱接地与透视也要成立。
- 确认错误后实际修正并重新审查。失败图留档；审核记录写明问题、修正和结论，最终交付只引用通过版本。

## 音频

1. 确认有音轨、时长正常、无爆音、截断和长静音。
2. 提取并转写音频，逐句对照已确认文本，检查漏字、改字、多读和重复。
3. 检查音色分工，旁白与主人公不得互换；无台词处不能出现额外人声。
4. 环境声和特效声服务画面；未要求时不加音乐。
5. 全片统一试听；转写、波形或语速计算只能辅助，不能代替听感。声音时间窗逐段对照分镜，原文拼接一致不等于实际音画同步通过。

## 技术参数

- 用媒体探测工具确认容器、编码、分辨率、画幅、帧率、时长和音轨；默认正式视频 720P。
- 文件须完整解码、首尾无损坏、移动端可打开。若格式不兼容，保留原始文件并另存标准 MP4 兼容版。
- 图像读取实际宽高，需原图直拷时核对源文件哈希；如有编辑、裁切或重采样记录其来源链。哈希相同只能证明文件一致，不能证明画面内容正确。

## 积分

- 任务前后查询当前积分，记录预计和实际消耗；不把历史余额当当前值。
- 下载或查询失败不等于生成失败，先按任务 ID 查状态。
- 首帧不合格不生成视频；整组仅局部高风险时拆出该镜头，避免重烧整组。
- 若只能从余额推算消耗，应明确说明。

## 文件与记录

用中文可读、含版本号的名称，例如 `镜头03_首帧_v02.png`、`镜头03-05_25秒_Seedance2.5_720P_v01.mp4`、`镜头03-05_提示词_v01.txt`。记录模型、任务 ID、时间、参数、参考文件、提示词、积分、审校结论和失败原因。

`07_最终交付`只放通过审校的：按剪辑顺序编号的视频、最终首帧/关键帧、完整提示词、镜头顺序与时长清单、必要技术和音频说明。失败版本进入 `99_淘汰版本`。

手工包逐条检查图片/音频编号与实际文件双向一致、各图用途与分镜时间覆盖、口播原文拼接、提示词字数及禁用操作者语句。清除过时进度和“待生成”声明。全部修改结束后重新构建文件清单与ZIP，检查CRC及清单哈希；不能在打包后改文件却继续交付旧包。按已授权范围分别报告图片、提示词、视频、新配音与实测验收状态。

## 对话交付

- 桌面端给清晰的本地可点击链接，并可打开关键成品预览。
- 手机端或远程控制时提供可直接预览的附件、内联媒体或产品支持的分享方式，不能只给本地路径。
- 汇报先说明哪些通过、哪些待复核，再给文件和积分，不让过程日志淹没结果。
